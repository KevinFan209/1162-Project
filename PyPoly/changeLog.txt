[2026-07-29] #22 全流程整合測試（無瀏覽器，以程式扮演兩位玩家跑完整局）
  方式：以 requests + socketio.Client 依前端實際送出的參數與順序，完整走過
        登入→建房→加入→開局→抓地圖→決定先後手→擲骰移動→冒險答題→購地→
        開合跳→換回合→結算→結果頁→離開登出。共 69 項斷言。
  結果：69 PASS / 0 FAIL，伺服器全程未拋例外。
  同時另跑邊界情境測試（斷線、重整、背景清理），發現下列問題（本輪未修）：

  【阻斷級】
  1. game.html:7355 定義了 startSyncLoop() 卻從未被呼叫 → 進遊戲後全程零心跳，
     後端 60 秒無心跳的背景清理會把玩家判定離線（實測 t=50s 即 is_online=0）。
     後果：管理員後台顯示遊玩中玩家為離線；重複登入防護失效（實測對局中可用
     同帳號再次登入成功）。lobby.html / WaitingRoom.html 皆有正確呼叫，可對照。
  2. 完全沒有斷線處理：main.py 無 sio disconnect handler，前端亦無「對手離線」
     監聽。玩家關分頁後仍留在 room['players']；決定先後手階段對手一斷線，
     handle_order_dice 永遠湊不滿 2 人 → 遊戲死鎖。另 triggerGameOver 只由
     players[1] 送結算，該玩家離線則整局永不產生結算資料。
  3. 殭屍房間永久累積：active_rooms 只有明確 leave/delete 才清除，無逾時回收。
     實測有房間在客戶端崩潰後以 status=gaming 存活整輪測試，新玩家加入回
     400「房間已滿」。大廳會逐漸堆滿進不去的滿員房。

  【中等】
  4. game.html:6443 用 myName === players[1] 判定大回合結束，但 players 是
     加入順序，finalizeGameStart 決定先後手時不重排該陣列 → 客人擲骰贏得先手時，
     房主的最後一回合會被吃掉，每局 50% 機率不公平。
  5. game.html:6506 的 settle payload 只送 {username, final_money, laps}，
     未送 jump_count → 結算報表的開合跳次數永遠是 0。
  6. profile.html 呼叫兩個不存在的 API（實測皆 404）：
     POST /auth/update-profile、POST /auth/send-otp-new-email。
  7. modal.html:199-203「25 回合」「30 回合」兩個 option 的 value 都誤植為 20。
  8. /rooms/create 未將房號正規化為大寫，但 verify/join/leave/kick/start 都有
